Хендл ⋮⋮ — єдина точка захвату. Активна картка піднімається (тінь + z-index), сусідні тьмяніють (opacity .5). Номер точки перераховується після відпускання.
Три жести на одній картці — розділені зони
Картка точки поєднує три незалежні жести без конфліктів:
• Свайп ліворуч (Відвідано/Видалити) — onPointerDown на всій картці (окрім хендла), горизонтальний drag за threshold.
• Перехід — onClick лише на тексті (назва/адреса/задачі) і шевроні, НЕ на всій картці — інакше клік конфліктує зі свайпом і drag. Невідвідана точка → деталі точки; відвідана → звіт про візит (заповнений або форма заповнення, якщо ще не збережено).
• Зміна порядку — onPointerDown тільки на хендлі ⋮⋮, з e.stopPropagation() (і на onClick теж) — щоб тап по номеру/хендлу не бабблився в клік «Звіт» і не запускав свайп.
Колонка з номером і хендлом — некликабельна зона (stopPropagation на onClick), розділяє жести фізично.

8b. Архів — 4+ днів тому (read-only)
Аптека Подорожник
Відвідано · 14 бер, 10:32
За межами 3-денного вікна — чистий перегляд: без свайпу, без кнопки "Відвідано", без переходу на звіт. Дата/час фактичної дії — підпис прямо на картці, а не окрема "додано пізніше".
Правила для минулих дат
• Звіт (шеврон, тап по рядку) — лише коли точка відвідана. Невідвідана точка не має куди переходити, звіту ще не існує.
• В межах 3-денного вікна заднього числа доступні свайп-дії "Відвідано" і "Видалити" — точно як сьогодні.
• Drag-ручка (6 крапок) не додається навіть у межах 3 днів — реордер минулого не має сенсу.
• Celebratory-оверлей "Молодець!" не показується в минулому навіть при 100% відвіданих точках — він доречний лише "в моменті" сьогодні.
• На майбутніх днях свайп точки відкриває лише "Видалити" — "Відвідано" не показується, бо відвідати ще не можна.
• "Додати точку"/"Додати маршрут" — лише для активного (сьогоднішнього) дня, майбутнього. Планування в минуле не має сенсу. Позаплановий візит додається окремою пунктирною кнопкою.
• За межами 3 днів — повний read-only: без свайпу, без дій, лише перегляд і підпис фактичного часу/дати відвідування на картці.
• Тап строчка/шеврон відкриває звіт (read-only) лише коли точка відвідана — для невідвіданої звіту ще не існує.
• Теорії застосовуються один раз при проєктуванні екрана; якщо елемент вже відповідає їм, додаткового обґрунтування чи повторної перевірки не потрібно.
• Підказка про 3-денне вікно — інлайн іконка "i" одразу після дати (не окремий рядок/картка, не в зоні тапу самої дати), тап показує спливаючу підказку. Це довідкова деталь, не основний захист від "запізно редагувати" — розглянути окрему позначку саме на межовому (третьому) дні, коли це реально критично.

Всі точки закрито — гарний результат
Backdrop — стандартний нейтральний `rgba(22,25,26,.42)`, як і всі інші оверлеї в кіті (без винятків для брендового кольору). Картка: 14px радіус, без тіні, тепліший фон `#F4F9F6`. Правило: колір смужки картки точки
Ліва вертикальна смужка (4px) картки точки відображає стан задач цієї точки, не довільний колір:
• Червона (#B23A3A) — є хоча б одна прострочена задача. Найвищий пріоритет: якщо серед задач точки є прострочена, смужка завжди червона, навіть якщо є ще й задачі на сьогодні.
• Жовтогаряча (#C98A22) — є задачі на сьогодні, прострочених немає.
• Зелена (#5A8F78) — задач немає (звичайна точка маршруту без прив'язаних задач).
Колір смужки й колір/іконка підпису задач під адресою завжди узгоджені — не можна мати червону смужку з жовтогарячим підписом чи навпаки.
Правило: екрани, дійсні лише для «сьогодні»
home-day-all-visited.dc.html («усі точки відвідано») та home-day-complete.dc.html («день виконано», celebratory-оверлей) моделюють стан, можливий лише сьогодні:
• Минулий день теж може мати всі точки відвіданими, але без лейбла «сьогодні» і без celebratory-оверлею (див. правило «Минулий день» вище) — це вже архів, не момент завершення.
• Майбутній день не може мати відвіданих точок узагалі — візит ще не стався.
Не використовувати ці два екрани як шаблон для минулого/майбутнього — для минулого є окремий, вже описаний паттерн.
Відомі прогалини (потребують рішення)
• Порожній день (0 маршрутів) — окремий екран `home-empty.dc.html`, підключається розробником
• Завантаження / помилка мережі — окремі екрани `loading-and-point.dc.html` (skeleton) і `visit-report-error.dc.html`
• Дуже довга назва точки — `text-overflow:ellipsis` (обрізка з трьома крапками)
• Ліміт маршрутів у списку — скрол, без пагінації
